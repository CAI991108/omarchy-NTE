# The repo cuts at 3.8.2 → 4.0: `main` is 4.x only, `tag omarchy-3.8.2` is the past

**Status:** accepted (2026-10-31) — **superseded in part by [ADR-0003](0003-keep-a-3-8-line.md)** (the 3.8 line is a long-lived branch now, not only a tag) **and by [ADR-0004](0004-defer-capture-to-2026-11-14.md)** (the `packages/` re-capture happens in the 2026-11-14 sync, together with the next config capture).

Omarchy 4.0 is not a version bump of 3.8.2: Hyprland config became Lua, `waybar`/`mako`/
`walker`/`hypridle` were deleted in favour of one Quickshell process, theme state moved
from `~/.config/omarchy/current/` to `~/.local/state/omarchy/current/`, and on `quattro`
the fcitx5 theme is generated by `omarchy-theme-set` itself (not true of the released
`v4.0.6`, where `bin/omarchy-theme-set-fcitx5` is still absent). A tree captured on 3.8.2 is therefore
about 19% action: 194 lines wholly dead, 139 lines that must be rewritten, and one
239-line hook that now duplicates shipped behaviour.

`main` therefore describes Omarchy 4.x. The 3.8.2 tree is frozen as the annotated tag
`omarchy-3.8.2` on `4ec86de`, and the tree itself was re-captured from a live 4.0 machine
rather than translated from the old files.

## Considered options

- **Dual-track directories** (`config/` + `config-3.8.2/`) — rejected: nobody will send
  commits down the 3.8.2 line, and the installer would split into two sets of
  assumptions (write-through symlinks, hook paths, theme state) for a machine nobody runs.
- **A `omarchy-4` long-lived branch, `main` left on 3.8.2** — rejected: the repo's value
  is "this is what the machine actually runs"; leaving `main` on a dead release makes
  every default a lie. A tag preserves the history just as well.
- **Translate `hypr/*.conf` into `hypr/*.lua` file by file** — rejected: `.conf` → `o.bind`
  is a semantic rewrite, so nothing proves the result is live. Even Omarchy's own
  `omarchy-upgrade-to-quattro` leaves the old `hyprland.conf` in place "for users to
  reference/port" instead of converting it. Translation also carries the stale pieces
  verbatim — the 239-line `fcitx5-follow` hook would have been ported straight into 4.0,
  where it duplicates `omarchy-theme-set-fcitx5` (again, `quattro` only).
- **Capture tooling (`bin/capture-config`) now** — rejected: the real payoff is the *next*
  generation. Writing a differ against a directory layout that 4.0 has only just settled
  is guessing; the procedure is written down in `docs/omarchy-4.md` instead, and 5.x is
  the point at which it becomes a script.

## Consequences

- **Capture criterion** (also in `AGENTS.md`): a file belongs in `config/` when it differs
  from `$OMARCHY_PATH/config/<same path>`, or when no shipped template exists and the file
  is deliberately maintained (units, `bin/`). Everything that merely reproduces Omarchy's
  defaults is dropped — `nvim/` (owned by the `omarchy-nvim` package), `btop.conf`,
  `herdr`'s upstream sample, `waybar/`, `mako/`, `hypridle.conf`, `elephant.service`,
  `brave-flags.conf`, `user-dirs.*`.
- **Capture granularity is a whole-file snapshot.** Templates are not merged, so a
  snapshot keeps the comments it was captured with. Accepted: it is the only way
  `shell.json` (rewritten by `omarchy bar`) can be restored, and it keeps deploy
  copy-only.
- `install.sh` becomes table-driven (`config/`, `dsh/`, `bin/` are rows) instead of
  special-casing `dsh/`; the four assumptions that had aged (write-through symlinks, three
  theme symlinks, `theme-set.d` hook, `waybar` restart advice) are re-stated against 4.0.
- The old tree is one `git show omarchy-3.8.2:config/...` away, so deletions in `main`
  are deliberate rather than lossy.
- `packages/` stays a 3.8.2-era snapshot for now; re-running `pacman -Qe` is a separate,
  human-reviewed step.
- **5.x criterion:** when the next generation lands, turn the `docs/omarchy-4.md`
  procedure into `bin/capture-config` and reconsider per-file capture. Do not add tickets
  or a map for a cut of this size (≈18 KB); the ADR is the record.
